# Modules

Bark uses `bark.toml` manifest files to manage project dependencies and metadata.

## Quick Start

```bash
# Create a new project with bark.toml
bark init

# Fetch all dependencies
bark get

# Update dependencies to latest versions
bark update
```

## bark.toml Structure

The manifest file has two sections: `[module]` for project metadata and `[dependencies]` for external modules.

```toml
[module]
name = "myapp"
version = "0.1.0"

[dependencies]
json = { git = "https://gitlab.com/bark-lang/modules/json", tag = "v1.0.0" }
```

### Module Section

| Field | Required | Description |
|-------|----------|-------------|
| name | yes | Project name |
| version | yes | Semantic version (e.g., "1.0.0") |

### Dependencies Section

Each dependency is a key-value pair where the key is the import name and the value specifies the source.

## Dependency Types

### Git Dependencies

Fetch modules from git repositories using `git` with an optional version specifier.

```toml
[dependencies]
# Tagged release (recommended for production)
json = { git = "https://gitlab.com/bark-lang/modules/json", tag = "v1.0.0" }

# Branch (tracks latest commits)
logger = { git = "https://gitlab.com/user/bark-logger", branch = "main" }

# Specific commit
crypto = { git = "https://example.com/crypto", rev = "abc123def456" }

# Default: uses main branch when no version specified
utils = { git = "https://gitlab.com/user/bark-utils" }
```

| Field | Description |
|-------|-------------|
| git | Repository URL (required) |
| tag | Git tag, e.g., "v1.0.0" |
| branch | Git branch, e.g., "main" |
| rev | Git commit hash |

Only one version specifier (tag, branch, or rev) should be used. If none is specified, defaults to `main` branch.

### Path Dependencies

Reference local modules using relative paths. Useful for development and monorepos.

```toml
[dependencies]
mylib = { path = "./lib/mylib" }
shared = { path = "../shared/utils" }
```

Paths are resolved relative to the project root (where bark.toml exists).

## Using Dependencies

Import dependencies by name in your bark code:

```bark
import "json"
import "logger" as log

fn main() {
  data > json.encode() > println()
  "Hello" > log.info()
}()
```

Import submodules by appending paths:

```bark
import "json/parser"
import "json/encoder" as enc
```

## CLI Commands

### bark init

Creates a new `bark.toml` in the current directory:

```bash
bark init
```

Generates:

```toml
[module]
name = "current_directory_name"
version = "0.1.0"

[dependencies]
```

### bark get

Fetches all dependencies defined in `bark.toml`:

```bash
bark get
```

- Downloads git dependencies to `~/.bark/modules/<name>/<version>/`
- Resolves path dependencies relative to project root
- Generates or updates `bark.lock`

### bark update

Re-fetches all dependencies, ignoring cached versions:

```bash
bark update
```

Use this to get the latest commits when tracking branches.

## bark.lock

The lockfile records exact resolved versions and checksums for reproducible builds. It is automatically generated by `bark get` and `bark update`.

```toml
# bark.lock - automatically generated, do not edit

[[module]]
name = "json"
version = "v1.0.0"
source = "git+https://gitlab.com/bark-lang/modules/json?tag=v1.0.0"
checksum = "sha256:abc123..."
```

Commit `bark.lock` to version control for reproducible builds across environments.

## Module Cache

Downloaded modules are cached at `~/.bark/modules/`. The cache structure is:

```text
~/.bark/modules/
  json/
    v1.0.0/
      module.bark
      ...
  logger/
    main/
      module.bark
      ...
```

## Example Project

**bark.toml:**

```toml
[module]
name = "web_api"
version = "1.0.0"

[dependencies]
json = { git = "https://gitlab.com/bark-lang/modules/json", tag = "v1.2.0" }
http = { git = "https://gitlab.com/bark-lang/modules/http", tag = "v1.0.0" }
utils = { path = "./lib/utils" }
```

**main.bark:**

```bark
import "json"
import "http"
import "utils"

fn main() {
  data > json.encode() > http.post("https://api.example.com/data")
}()
```

## Module Visibility

Only functions marked with `pub` are accessible when imported:

```bark
// lib/utils/module.bark
module utils

pub fn helper() {
  // accessible via utils.helper()
}()

fn internal() {
  // not accessible from imports
}()
```
